Generative AI

ChatGPT, image generators and voice clones all do the same basic thing: they learned what real text, pictures or sound look like, and now they produce new examples that fit the pattern. No understanding, no intentions. A chatbot is a very large version of the autocomplete from the last lesson.

Try it: be the language model

This tiny model has read about twenty sentences of recipe instructions and counted which word tends to follow which. Click a suggestion to add it, or let it pick for you. That loop, score every possible next word, pick one, repeat, is exactly how GPT writes. GPT just reads far more context and has billions of numbers instead of a word count table.

Next-word probabilities

Temperature reshapes the odds before picking. Low = always the safest word (boring, repetitive). High = long shots get a real chance (creative, then nonsense). Chatbots have this same dial.

Baby GPT: a transformer from scratch

The 8 Generative AI/Baby_GPT notebook trains a small GPT on recipes. Three ideas do all the work:

  1. Tokens. Text is chopped into word pieces and each piece becomes an ID number.
  2. Attention. For every position, the model decides which earlier tokens matter. In "preheat the oven, then put the tray in it", attention links "it" back to "oven". This is what the trigram model in lesson 08 couldn't do.
  3. Next-token training. Show it a chunk of text, ask it to guess each following token, nudge the weights when it's wrong. Repeat millions of times.

One attention head in PyTorch

import torch
import torch.nn as nn
from torch.nn import functional as F

class Head(nn.Module):
    def __init__(self, n_embd, head_size, block_size):
        super().__init__()
        self.key   = nn.Linear(n_embd, head_size, bias=False)
        self.query = nn.Linear(n_embd, head_size, bias=False)
        self.value = nn.Linear(n_embd, head_size, bias=False)
        # Mask so a token can only look at tokens before it
        self.register_buffer("tril", torch.tril(torch.ones(block_size, block_size)))

    def forward(self, x):
        B, T, C = x.shape
        k, q = self.key(x), self.query(x)
        scores = q @ k.transpose(-2, -1) * k.shape[-1] ** -0.5   # how relevant is each token?
        scores = scores.masked_fill(self.tril[:T, :T] == 0, float("-inf"))
        weights = F.softmax(scores, dim=-1)                       # turn scores into percentages
        return weights @ self.value(x)                            # blend the relevant tokens

Generating text

@torch.no_grad()
def generate(model, idx, max_new_tokens, temperature=1.0):
    for _ in range(max_new_tokens):
        logits, _ = model(idx[:, -block_size:])        # scores for every token in the vocab
        probs = F.softmax(logits[:, -1, :] / temperature, dim=-1)
        next_id = torch.multinomial(probs, num_samples=1)  # roll the weighted dice
        idx = torch.cat([idx, next_id], dim=1)           # append and go again
    return idx

That loop is the demo above, with a neural network in place of the count table.

RAG: give the model an open book

A language model only knows what was in its training data, and when it doesn't know it still produces something fluent. That's a "hallucination". Retrieval-augmented generation fixes much of this: search your own documents first, paste the best matches into the prompt, and ask the model to answer from them.

import numpy as np
from sentence_transformers import SentenceTransformer

docs = ["Our office is open 9am to 5pm, Monday to Friday.",
        "Refunds are processed within 14 days.",
        "The Wi-Fi password is on the fridge."]

embedder = SentenceTransformer("all-MiniLM-L6-v2")
doc_vecs = embedder.encode(docs, normalize_embeddings=True)

def retrieve(question, k=1):
    q = embedder.encode([question], normalize_embeddings=True)[0]
    scores = doc_vecs @ q                 # cosine similarity, like lesson 08
    return [docs[i] for i in np.argsort(scores)[::-1][:k]]

question = "How long do refunds take?"
context = "\n".join(retrieve(question))
prompt = f"Answer using only this context:\n{context}\n\nQuestion: {question}"
# send `prompt` to any chat model

Notice the search step is the same embeddings + cosine similarity you met in lessons 04 and 08. See 8 Generative AI/RAG for the full and LangChain versions.

Making images: diffusion

Image generators like Stable Diffusion are trained by taking real photos, adding random noise a little at a time until they're pure static, and teaching a network to undo one step of noise. To make a new picture you start from fresh static and run the "undo" step many times. Your text prompt steers each step towards images that match the words.

// generation, in pseudocode

image = random_noise()
for step in range(50):
    image = image - predict_noise(image, step, prompt)

Deepfakes and real risks

The same tools that make a fun image can fake a face or a voice. The real risks of generative AI are more ordinary than robots taking over:

  • Confident mistakes: fluent answers that are simply wrong
  • Deepfakes and scams: fake video, voice and images of real people
  • Bias: models repeat the patterns, good and bad, of their training data
  • Privacy and copyright: what went into the training data, and who agreed to it

Detection is also machine learning. 8 Generative AI/Deepfake_Detection trains a CNN (lesson 06) to spot the small artefacts generators leave behind.
